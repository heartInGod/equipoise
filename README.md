# Equipoise

> 一个真正会打牌的 AI 牌手。

---

## 一、产品介绍

Equipoise 让 AI 以职业牌手的身份参与牌局。它不止于算出答案，而是像一位真正的牌手那样思考：看懂局面、记住对手，并为自己的每一次行动讲清理由。

它可以是**随叫随到的教练**——打牌时随时请教，规则、打法、赔率，得到的都是带理由的建议；也可以是**桌边的牌手**——从看牌到行动，替你把一场牌局完整打完；更是**事后的复盘师**——每一手该不该偏移、该不该收手，它都能说给你听。

支撑这些的，是它接近职业牌手的能力：

- **读得懂局面**：不只看手里的牌，更读懂位置、行动线、底池与对手的意图。
- **记得住对手**：对每位对手保持长期记忆，越打越懂他们的习惯与破绽。
- **说得清理由**：每一次行动都解释「为什么」，依据与风险清清楚楚。
- **藏得住意图**：关键时刻保留随机性，不露规律、不被人读透。
- **越打越会**：把每一手的得失沉淀成经验，持续修正自己的判断。

```
                           │
        ┌──────────────────┼──────────────────────┐
        ▼                  ▼                      ▼
┌───────────────┐  ┌─────────────────┐  ┌─────────────────────┐
│  tools/state   │  │  session_prompt  │  │      bot_core        │
│  截图→文字状态  │  │  prompt+画像+流水│  │  状态机/动作/对冲/    │
│  OCR+模板识牌  │  │  (注入知识文档)  │  │  长连接/截图/AdbIO    │
└───────────────┘  └─────────────────┘  └─────────────────────┘
        │                  │                      │
        └──────────────────┼──────────────────────┘
                           ▼
                  大模型决策（Anthropic / OpenAI / Gemini / Chat）
                           │
                           ▼
                    apply_mix + 随机数 R → 最终动作
                           │
                           ▼
                    AdbIO 常驻 adb shell 点击
```

| 模块 | 职责 |
|---|---|
| `poker_bot.py` | 命令行入口、模型配置读取、通用模型调用 |
| `bot_core.py` | 机器人核心：每帧状态机、动作映射、对冲请求、长连接池、后台截图、常驻 adb shell、本地规则兜底 |
| `session_prompt.py` | session 模式 prompt：开局长 system + 对手画像注入 + 本手逐动作记录 + 混合策略 |
| `tools/state.py` | 截图 → 文字状态：OCR + 模板识牌、听牌/胜率/底池计算 |
| `tools/table.py` | 2~8 人桌通用模型：位置、行动线解析、翻前范围基线 |
| `tools/seats.py` | 多人桌座位识别：昵称/筹码/下注/D 位归座 |
| `tools/players.py` + `oppdb.py` | 全局对手库（SQLite）：跨桌累计统计、画像查询 |
| `rule.md` / `technology.md` / `gto.md` | 知识库：规则 / 实战技巧 / GTO 理论（同时是 agent 的决策依据） |
| `tables/` | 每桌一个目录：`table.md` · `hands.jsonl`（流水）· `<opp>.md`（画像） |

## 三、与 Agent 结合的亮点

**1. 可解释决策**
每次决策输出带 `why`（理由）+ 计算算式 + 偏移证据 + 风险，不是黑盒出动作。

**2. 画像维护闭环**
agent 读画像做偏移 → 每手结束代码记录流水 → 每 N 手 agent 异步更新画像 → 下一手用新画像，形成自我学习闭环。

**3. 混合策略 + 随机数 R**
agent 输出「动作 + 频率」，代码用随机数 R 按累计频率选最终动作——既保留 GTO 的混合策略，又避免形成可读模式。

**4. 会话记忆与 prompt 缓存**
开局长 system（prompt caching）+ 手内多轮短消息，每次决策注入本手完整记录与对手画像，agent 拥有跨手上下文记忆。
